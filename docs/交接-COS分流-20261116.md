## 1. 为什么做这件事

90CN 轻量服务器出口只有 **14 Mbps（1.75 MB/s）**。
登录器全量包 130MB、PVF 126MB、DNF.exe 112MB 如果都从网关下发，
一次发版直接把上行打满，在线玩家卡顿。

方案：**全量包走腾讯云 COS，增量仍走网关**。
网关只出清单，字节由 COS 直接发给玩家，服务器不参与传输。

## 4. 执行步骤

### 4.1 构建并部署网关

```bash
cd E:/DNF-Server/Gateway-GO
git pull gitee feature/s5a3-standalone     # 确认在 3d427ad 或之后
sh build.sh                                 # → dist/linux-amd64/

# 上传（/tmp 中转）
scp dist/linux-amd64/s5a3-gateway <server>:/tmp/s5a3-gateway.new

# 服务器上（低峰！会掉线约 10 秒）
sudo bash -c '
set -e
TS=$(date +%Y%m%d-%H%M%S)
cp -a /opt/s5a3/gateway/s5a3-gateway /opt/s5a3/gateway/backups/s5a3-gateway.bak-$TS
systemctl stop s5a3-gateway
install -m 755 /tmp/s5a3-gateway.new /opt/s5a3/gateway/s5a3-gateway
systemctl start s5a3-gateway
sleep 4; systemctl is-active s5a3-gateway
systemctl show -p MainPID --value s5a3-gateway
'
```

> ★ 判「真换了」只看 `MainPID` 是否变，`sha256sum` 全绿会骗人（`install` 换 inode，
> 不重启仍跑旧代码）。

### 4.2 发登录器 2.7.5

exe 在本机 `Launcher-WPF/dist/s5a3-90cn/SimpleLauncher_s5a3_90cn_2.7.5.exe`
（sha256 = `C6261A7B…`，与 COS 上那份一致）。

**必须走 admin API，不要 scp 覆盖 current.exe** —— 手拷不写 `history/`，
客户端就拿不到增量，只能全量重下（2026-11-16 的事故根因）。

```bash
KEY=$(sudo grep -oP 'S4A21_ADMIN_AUTH_KEY=\K.*' /opt/s5a3/gateway/gateway.env)
curl -sk -X POST https://127.0.0.1:8443/api/admin/launcher/upload \
  -H "X-Auth-Key: $KEY" \
  -F "file=@/tmp/SimpleLauncher_s5a3_90cn_2.7.5.exe" \
  -F "version=2.7.5" \
  -F "name=2.7.5 PVF full update + COS"
```

### 4.3 验证（缺一不可）

```bash
# ① 清单 full_url 是否指向 COS
curl -sk https://127.0.0.1:8080/api/launcher/update
# 期望：full_url = https://s5a3-client-....cos.ap-shanghai.myqcloud.com/launcher/C6261A7B....exe
#       hash = C6261A7B...（与 COS 对象名一致）

# ② policy 是否带 PVF 全量地址
curl -sk "https://127.0.0.1:8080/api/launcher/policy?game=s5a3"
# 期望：pvf.full_url = .../pvf/A3CB400A....pvf

# ③ 增量必须仍然可用（不能 404）
curl -sk -o /dev/null -w '%{http_code}\n' \
  "https://127.0.0.1:8080/api/launcher/update/delta?from=1A9D15C22C44CF17CF92E27620BCF9A0A06F0C0A0DAAE9280F04B95A1D79FABF"
# 期望 200；如果是 404 ⇒ history 缺失，停下来查

# ④ COS 对象可公开下载
curl -sI <full_url 的值> | head -3      # 期望 200 + Content-Length

# ⑤ 网关限速仍生效（应 ≈1MB/s）
for i in $(seq 1 12); do curl -sk -o /dev/null -w '%{size_download}' --max-time 10 \
  https://127.0.0.1:8080/api/launcher/update/exe > /tmp/n$i.txt & done; wait
awk '{s+=$1} END{printf "%.2f MB/s\n", s/10/1048576}' /tmp/n*.txt
```

### 4.4 观察

发版后玩家会陆续收到 2.7.5 可选更新（`min_version` 仍是 2.7.3，不强制）。
`2.7.4 → 2.7.5` 是同机构建，增量应该是**几百 KB**；
如果又是几十 MB，说明构建机变了，检查 `dist` 是否在同一环境下产出。

## 6. 已知边界

- **增量必须留在网关**：按需增量（`?from=<hash>`）是请求时现场生成的，
  COS 忽略 query 会返回基线不符的包，客户端校验失败后回退全量，反而更糟。
- 限速参数只接受**整数 MB/s**（当前 1MB/s + 并发 4），填 0.5 会回落默认 8。
- PVF 全量只在「有增量但失败」时兜底；完全没有 delta 的老网关仍走原提示路径。
